## 4주차 반응형 수정

### 확인할 문제
1. 기존 웹페이지는 데스크탑 화면 중심으로 구성되어 있어 모바일과 같이 화면이 작아질 경우 메뉴, 클래스 소개 카드, 수강 신청 영역이 좁게 보였다.
2. 클래스별 내용의 길이에 따라 클래스 소개 카드의 크기와 배치가 일정하지 않아 전체적으로 정돈되지 않아 보였다.

### 수정한 내용

- 콘텐츠에 width와 max-width를 함께 사용하여 화면 크기에 맞게 표시되도록 했다.
- 클래스 소개 카드 목록을 반응형 grid로 변경하여 카드의 크기와 배치를 일정하게 정돈했다.
- 768픽셀 이하에서 메뉴, 클래스 소개 카드, 수강 신청 입력창과 버튼을 한 열로 배치했다.
- 모바일 화면에 맞게 글자 크기와 여백을 조정했다.

### 확인한 화면 너비
1100px / 769px / 768px / 390px

### 확인 결과
- 화면 너비가 작아지면 메뉴와 클래스 소개 카드, 수강 신청 폼이 한 열로 변경되는 것을 확인했다.
- 모바일 화면에서도 콘텐츠가 화면 너비에 맞게 표시되고 각 영역을 편하게 확인할 수 있었다.
- 클래스 소개 카드의 크기와 간격이 일정하게 배치되어 이전보다 전체적으로 정돈된 화면을 확인할 수 있었다.

## JavaScript '수강 신청' 기능 구현

### 1. 사용자는 무엇을 하는가?
- 사용자는 홈페이지의 수강 신청 영역에서 이름을 입력한다.
- '수강 신청하기' 버튼을 클릭하여 신청을 진행한다.
- 이름을 입력하지 않은 경우 안내 메시지를 확인한다.

### 2. 화면에서는 무엇이 바뀌는가?
- 이름을 입력하지 않으면 '이름을 입력한 뒤 수강 신청해주세요.'라는 메시지가 표시된다.
- 이름을 입력하고 신청하면 'OOO님의 수강 신청이 완료되었습니다.'라는 메시지가 표시된다.
- 신청 완료 메시지에 초록색 배경 스타일이 적용된다.
- 이름을 입력하고 수강 신청을 완료하면 버튼의 문구가 '신청 완료'로 변경되고 비활성화된다.

### 3. 어떤 코드로 연결했는가?
- `document.querySelector()`로 이름 입력창, 신청 버튼, 신청 폼, 안내 메시지 요소를 선택했다.
- `addEventListener("submit", handleRegister)`로 폼 제출 이벤트를 연결했다.
- `event.preventDefault()`로 폼 제출 시 페이지가 새로고침되는 것을 방지했다.
- `value.trim()`과 `if` 조건문으로 이름 입력 여부를 확인했다.
- `makeRegisterMessage()` 함수와 `textContent`를 사용하여 신청 결과 메시지를 변경했다.
- `classList.add("is-success")`로 완료 메시지의 스타일을 적용하고, `disabled`로 버튼을 비활성화했다.

## JavaScript '클래스 선택' 기능 구현

### 1. 사용자는 무엇을 하는가?
- 사용자는 클래스 소개 영역에서 원하는 클래스의 탭을 클릭한다.
- 선택한 클래스의 이름과 설명을 확인한다.
- 수강 신청 영역에서 원하는 클래스를 선택하고 신청할 수 있다.

### 2. 화면에서는 무엇이 바뀌는가?
- 선택한 클래스의 설명 카드만 표시되고 나머지 클래스의 설명은 숨겨진다.
- 선택한 탭의 배경색이 변경되어 현재 선택한 클래스를 구분할 수 있다.
- 다른 탭을 클릭하면 이전 클래스의 설명이 사라지고 새로운 클래스의 설명이 표시된다.
- 수강 신청을 완료하면 신청자의 이름과 선택한 클래스가 완료 메시지에 표시된다.

### 3. 어떤 코드로 연결했는가?
- `document.querySelectorAll()`로 클래스 탭과 설명 영역을 선택했다.
- `addEventListener("click", handleClassTabClick)`로 탭 클릭 이벤트를 연결했다.
- `event.currentTarget`과 `dataset.target`으로 클릭한 탭과 연결된 설명 영역을 확인했다.
- `forEach()`와 `classList.add()`, `classList.remove()`로 선택한 탭의 스타일을 변경했다.
- `hidden` 속성을 사용하여 선택한 클래스의 설명만 표시했다.
- `aria-selected` 속성으로 탭의 선택 상태를 표시했다.
- `select` 요소의 `value`를 가져와 수강 신청 완료 메시지에 선택한 클래스를 함께 표시했다.

### 4. 실행 확인 및 테스트 결과
- 1100px, 768px, 390px 화면 너비에서 콘텐츠가 잘리지 않고 정상적으로 표시되는 것을 확인했다.
- `click` 이벤트를 통해 6개 클래스 탭과 무료 체험 안내 버튼이 정상적으로 작동하는 것을 확인했다.
- `input` 이벤트를 통해 이름 입력 시 글자 수가 변경되는 것을 확인했다.
- `change` 이벤트를 통해 체크박스 선택에 따라 안내 문구, 스타일, 버튼 상태가 변경되는 것을 확인했다.
- 클래스 탭 전환 후에도 기존 수강 신청 및 무료 체험 기능이 정상적으로 유지되는 것을 확인했다.

## 7주차 사용자 흐름 기반 프로토타입 구현

### 1. 사용자와 목표

- **사용자:** 초이스 댄스 스튜디오에서 수강을 희망하는 사람
- **목표:** 신청자 정보와 원하는 수강 조건을 입력하고, 신청 내용을 확인하여 수강 신청 절차를 완료한다.

### 2. 사용자의 흐름

1. '수강 신청 시작하기' 버튼을 클릭하여 안내 팝업을 확인하고, '신청 시작하기' 버튼을 눌러 신청 절차를 시작한다.
2. 신청자 이름과 휴대전화 번호를 입력한다. 입력이 누락되거나 형식이 올바르지 않으면 오류 안내를 확인하고 수정한다.
3. 원하는 댄스 클래스와 수강 유형을 선택한다. Mix 4회를 선택한 경우 서로 다른 두 클래스를 선택한다.
4. 입력한 신청자 정보와 수강 조건을 확인한다. 필요한 경우 '이전' 버튼을 눌러 내용을 수정한다.
5. '신청 완료하기' 버튼을 눌러 신청 절차를 완료한다.
6. 완료 안내를 확인하고, 필요한 경우 '다시 신청하기' 버튼을 눌러 새로운 신청을 시작한다.

### 3. 인터랙션 시나리오

#### 1) 수강 신청 시작

- **행동·이벤트:** 사용자가 '수강 신청 시작하기' 버튼을 클릭한다.
- **조건:** 안내 팝업에서 '돌아가기' 또는 '신청 시작하기'를 선택했는가?
- **반응·다음 상태:** `dialog` 요소를 이용한 안내 팝업이 표시된다. '돌아가기'를 누르면 팝업이 닫히고 시작 화면에 머무른다. '신청 시작하기'를 누르면 신청자 정보 입력 단계로 이동한다.

#### 2) 신청자 정보 입력

- **행동·이벤트:** 사용자가 이름과 휴대전화 번호를 입력하고 '수강 조건 선택하기' 버튼을 클릭한다.
- **조건:** 이름이 입력되었으며 휴대전화 번호가 올바른 형식인가?
- **반응·다음 상태:** 입력값이 누락되거나 형식이 올바르지 않으면 해당 입력창에 오류 메시지와 스타일을 표시한다. 올바르게 입력하면 신청 정보를 유지한 상태로 수강 조건 선택 단계로 이동한다.

#### 3) 수강 조건 선택

- **행동·이벤트:** 사용자가 원하는 댄스 클래스와 수강 유형을 선택하고 '신청 내용 확인하기' 버튼을 클릭한다.
- **조건:** 클래스와 수강 유형을 선택했는가? Mix 4회 선택 시 서로 다른 두 클래스를 선택했는가?
- **반응·다음 상태:** 필수 항목이 누락되거나 Mix 4회에서 동일한 클래스를 선택하면 오류 메시지를 표시한다. 조건을 충족하면 선택 정보를 저장하고 신청 내용 확인 단계로 이동한다. '이전' 버튼을 누르면 신청자 정보 입력 단계로 돌아간다.

#### 4) 신청 내용 확인

- **행동·이벤트:** 사용자가 이름, 휴대전화 번호, 신청 클래스, 수강 유형을 확인하고 '이전' 또는 '신청 완료하기' 버튼을 클릭한다.
- **조건:** 사용자가 이전 단계로 이동하는가, 신청 절차를 완료하는가?
- **반응·다음 상태:** '이전' 버튼을 누르면 기존 입력값을 유지한 상태로 수강 조건 선택 단계로 돌아간다. '신청 완료하기' 버튼을 누르면 완료 안내 화면으로 이동한다.

#### 5) 신청 완료 및 다시 신청

- **행동·이벤트:** 사용자가 신청 완료 안내를 확인하고 '다시 신청하기' 버튼을 클릭한다.
- **조건:** 다시 신청하기를 선택했는가?
- **반응·다음 상태:** 신청자 정보와 수강 조건을 초기화하고 첫 번째 입력 단계로 이동한다. 새로운 신청을 진행할 수 있도록 입력 화면을 표시한다.

### 4. 구현 내용

- 기존 수강 신청 영역을 신청자 정보 입력, 수강 조건 선택, 신청 내용 확인의 3단계 프로토타입으로 변경했다.
- HTML의 `dialog` 요소와 JavaScript의 `showModal()`, `close()`를 사용하여 수강 신청 안내 팝업을 구현했다.
- `showStep()` 함수와 `hidden` 속성을 사용하여 현재 단계에 해당하는 화면만 표시하도록 했다.
- 진행 단계 표시 영역을 추가하여 사용자가 현재 신청 단계를 확인할 수 있도록 했다.
- 이름의 입력 여부와 휴대전화 번호 형식을 검사하고, 오류가 발생하면 안내 메시지와 입력창 스타일을 변경하도록 했다.
- 휴대전화 번호 입력 시 `input` 이벤트를 사용하여 `010-1234-5678` 형식으로 자동 변환되도록 했다.
- 수강 유형 선택에 `change` 이벤트를 연결하여 Mix 4회를 선택하면 두 번째 클래스 선택창이 나타나도록 했다.
- Mix 4회 선택 시 두 클래스가 서로 다른지 검사하는 조건문을 추가했다.
- `formData` 객체를 사용하여 단계 이동 시 입력한 신청 정보를 유지하도록 했다.
- 신청 내용 확인 단계에서 이름, 휴대전화 번호, 클래스, 수강 유형을 표시하도록 했다.
- '이전' 버튼을 통해 이전 단계로 돌아가 입력 정보를 수정할 수 있도록 했다.
- `submit` 이벤트와 `event.preventDefault()`를 사용하여 페이지 새로고침 없이 신청 완료 화면으로 전환되도록 했다.
- '다시 신청하기' 버튼을 클릭하면 입력값과 오류 상태가 초기화되도록 했다.
- 기존 클래스 소개 탭과 무료 체험 수업 기능을 유지하고, 단계형 수강 신청 영역에 반응형 CSS를 적용했다.

### 5. 실행 확인 및 테스트 결과

- 수강 신청 시작 버튼을 클릭하면 안내 팝업이 표시되고, '돌아가기'와 '신청 시작하기' 버튼이 정상적으로 작동하는 것을 확인했다.
- 이름과 휴대전화 번호가 비어 있으면 오류 메시지가 표시되고 다음 단계로 이동하지 않는 것을 확인했다.
- 휴대전화 번호를 입력하면 `010-1234-5678` 형식으로 자동 변환되는 것을 확인했다.
- 이름과 휴대전화 번호를 올바르게 입력하면 수강 조건 선택 단계로 이동하는 것을 확인했다.
- Mix 4회 선택 시 두 번째 클래스 선택창이 표시되는 것을 확인했다.
- Mix 4회에서 두 번째 클래스를 선택하지 않거나 동일한 클래스를 선택하면 오류 메시지가 표시되는 것을 확인했다.
- 서로 다른 두 클래스를 선택하면 신청 내용 확인 단계로 정상적으로 이동하는 것을 확인했다.
- Mix 4회에서 일반 수강 유형으로 변경하면 두 번째 클래스 선택창이 사라지고 신청 내용에도 반영되는 것을 확인했다.
- '이전' 버튼을 눌러 앞 단계로 이동해도 입력값이 유지되며, 수정한 정보가 최종 확인 화면에 반영되는 것을 확인했다.
- 신청 완료 화면이 정상적으로 표시되고, '다시 신청하기' 버튼을 누르면 입력값과 선택 상태가 초기화되는 것을 확인했다.
- 1100px, 768px, 390px 화면 너비에서 안내 팝업, 진행 단계, 입력창, 버튼 및 신청 내용이 화면 크기에 맞게 표시되는 것을 확인했다.
- 기존 클래스 소개 탭과 무료 체험 수업 기능이 정상적으로 유지되는 것을 확인했다.
