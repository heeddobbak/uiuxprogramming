# 초이스 댄스 스튜디오

춤을 배우고 싶은 사용자가 클래스 정보를 살펴보고 수강 신청 절차를 체험하는 웹 프로토타입입니다. 현재 구현 기준은 아래 9주차 설명이며, 7~8주차를 포함한 이전 내용은 당시의 개발 기록입니다. 실제 신청 접수나 서버 저장은 하지 않습니다.

## 4주차 반응형 수정

### 확인할 문제
1. 기존 웹페이지는 데스크탑 화면 중심으로 구성되어 있어 모바일과 같이 화면이 작아질 경우 메뉴, 클래스 소개 카드, 수강 신청 영역이 좁게 보였다.
2. 클래스별 내용의 길이에 따라 클래스 소개 카드의 크기와 배치가 일정하지 않아 전체적으로 정돈되지 않아 보였다.

### 수정한 내용

- 콘텐츠에 width와 max-width를 함께 사용하여 화면 크기에 맞게 표시되도록 했다.
- 클래스 소개 카드 목록을 반응형 grid로 변경하여 카드의 크기와 배치를 일정하게 정돈했다.
- 768픽셀 이하에서 메뉴, 클래스 소개 카드, 수강 신청 입력창과 버튼을 한 열로 배치했다.
- 모바일 화면에 맞게 글자 크기와 여백을 조정했다.

### 확인한 화면 너비
1100px / 769px / 768px / 390px

### 확인 결과
- 화면 너비가 작아지면 메뉴와 클래스 소개 카드, 수강 신청 폼이 한 열로 변경되는 것을 확인했다.
- 모바일 화면에서도 콘텐츠가 화면 너비에 맞게 표시되고 각 영역을 편하게 확인할 수 있었다.
- 클래스 소개 카드의 크기와 간격이 일정하게 배치되어 이전보다 전체적으로 정돈된 화면을 확인할 수 있었다.

## 이전 주차 기록: JavaScript '수강 신청' 기능 구현

> 아래는 단계형 흐름 도입 전의 구현 기록입니다. 현재는 신청자 정보·수강 조건·확인 단계를 거쳐 완료 화면을 표시합니다.

### 1. 사용자는 무엇을 하는가?
- 사용자는 홈페이지의 수강 신청 영역에서 이름을 입력한다.
- '수강 신청하기' 버튼을 클릭하여 신청을 진행한다.
- 이름을 입력하지 않은 경우 안내 메시지를 확인한다.

### 2. 화면에서는 무엇이 바뀌는가?
- 이름을 입력하지 않으면 '이름을 입력한 뒤 수강 신청해주세요.'라는 메시지가 표시된다.
- 이름을 입력하고 신청하면 'OOO님의 수강 신청이 완료되었습니다.'라는 메시지가 표시된다.
- 신청 완료 메시지에 초록색 배경 스타일이 적용된다.
- 이름을 입력하고 수강 신청을 완료하면 버튼의 문구가 '신청 완료'로 변경되고 비활성화된다.

### 3. 어떤 코드로 연결했는가?
- `document.querySelector()`로 이름 입력창, 신청 버튼, 신청 폼, 안내 메시지 요소를 선택했다.
- `addEventListener("submit", handleRegister)`로 폼 제출 이벤트를 연결했다.
- `event.preventDefault()`로 폼 제출 시 페이지가 새로고침되는 것을 방지했다.
- `value.trim()`과 `if` 조건문으로 이름 입력 여부를 확인했다.
- `makeRegisterMessage()` 함수와 `textContent`를 사용하여 신청 결과 메시지를 변경했다.
- `classList.add("is-success")`로 완료 메시지의 스타일을 적용하고, `disabled`로 버튼을 비활성화했다.

## JavaScript '클래스 선택' 기능 구현

### 1. 사용자는 무엇을 하는가?
- 사용자는 클래스 소개 영역에서 원하는 클래스의 탭을 클릭한다.
- 선택한 클래스의 이름과 설명을 확인한다.
- 수강 신청 영역에서 원하는 클래스를 선택하고 신청할 수 있다.

### 2. 화면에서는 무엇이 바뀌는가?
- 선택한 클래스의 설명 카드만 표시되고 나머지 클래스의 설명은 숨겨진다.
- 선택한 탭의 배경색이 변경되어 현재 선택한 클래스를 구분할 수 있다.
- 다른 탭을 클릭하면 이전 클래스의 설명이 사라지고 새로운 클래스의 설명이 표시된다.
- 현재는 신청 내용 확인 화면에 신청자의 이름과 선택한 클래스를 표시하고, 완료 화면에는 신청자의 이름과 절차 완료 안내를 표시한다.

### 3. 어떤 코드로 연결했는가?
- `document.querySelectorAll()`로 클래스 탭과 설명 영역을 선택했다.
- `addEventListener("click", handleClassTabClick)`로 탭 클릭 이벤트를 연결했다.
- `event.currentTarget`과 `dataset.target`으로 클릭한 탭과 연결된 설명 영역을 확인했다.
- `forEach()`와 `classList.add()`, `classList.remove()`로 선택한 탭의 스타일을 변경했다.
- `hidden` 속성을 사용하여 선택한 클래스의 설명만 표시했다.
- `aria-selected` 속성으로 탭의 선택 상태를 표시했다.
- `select` 요소의 `value`를 가져와 현재 신청 내용 확인 화면에 선택한 클래스를 표시한다.

### 4. 실행 확인 및 테스트 결과
- 1100px, 768px, 390px 화면 너비에서 콘텐츠가 잘리지 않고 정상적으로 표시되는 것을 확인했다.
- `click` 이벤트를 통해 6개 클래스 탭과 무료 체험 안내 버튼이 정상적으로 작동하는 것을 확인했다.
- `input` 이벤트를 통해 이름 입력 시 글자 수가 변경되는 것을 확인했다.
- `change` 이벤트를 통해 체크박스 선택에 따라 안내 문구, 스타일, 버튼 상태가 변경되는 것을 확인했다.
- 클래스 탭 전환 후에도 기존 수강 신청 및 무료 체험 기능이 정상적으로 유지되는 것을 확인했다.

## 7주차 사용자 흐름 기반 프로토타입 구현

### 1. 사용자와 목표

- **사용자:** 초이스 댄스 스튜디오에서 수강을 희망하는 사람
- **목표:** 신청자 정보와 원하는 수강 조건을 입력하고, 신청 내용을 확인하여 수강 신청 절차를 완료한다.

- **핵심 행동:** 신청자 정보 입력 → 클래스·수강 유형 선택 → 신청 내용 확인 → 완료 버튼 선택
- **완료 조건:** 필수 정보와 수강 조건의 검증을 통과하고, 확인 단계에서 ‘신청 완료하기’를 눌러 완료 안내 화면이 표시되면 목표 달성으로 본다.

### 2. 사용자의 흐름 (5단계)

1. '수강 신청 시작하기' 버튼을 클릭하여 안내 팝업을 확인하고, '신청 시작하기' 버튼을 눌러 신청 절차를 시작한다.
2. 신청자 이름과 휴대전화 번호를 입력한다. 입력이 누락되거나 형식이 올바르지 않으면 오류 안내를 확인하고 수정한다.
3. 원하는 댄스 클래스와 수강 유형을 선택한다. Mix 4회를 선택한 경우 서로 다른 두 클래스를 선택한다.
4. 입력한 신청자 정보와 수강 조건을 확인한다. 필요한 경우 '이전' 버튼을 눌러 내용을 수정한다.
5. '신청 완료하기' 버튼을 눌러 완료 안내를 확인한다. 필요한 경우 '다시 신청하기'를 눌러 입력·선택·오류·확인 내용·완료 메시지를 초기화하고 신청자 정보 단계로 돌아간다.

### 3. 인터랙션 시나리오

#### 1) 수강 신청 시작

- **행동·이벤트:** 사용자가 '수강 신청 시작하기' 버튼을 클릭한다.
- **조건:** 안내 팝업에서 '돌아가기' 또는 '신청 시작하기'를 선택했는가?
- **반응·다음 상태:** `dialog` 요소를 이용한 안내 팝업이 표시된다. '돌아가기'를 누르면 팝업이 닫히고 시작 화면에 머무른다. '신청 시작하기'를 누르면 신청자 정보 입력 단계로 이동한다.

#### 2) 신청자 정보 입력

- **행동·이벤트:** 사용자가 이름과 휴대전화 번호를 입력하고 '수강 조건 선택하기' 버튼을 클릭한다.
- **조건:** 이름이 입력되었으며 휴대전화 번호가 올바른 형식인가?
- **반응·다음 상태:** 입력값이 누락되거나 형식이 올바르지 않으면 해당 입력창에 오류 메시지와 스타일을 표시한다. 올바르게 입력하면 신청 정보를 유지한 상태로 수강 조건 선택 단계로 이동한다.

#### 3) 수강 조건 선택

- **행동·이벤트:** 사용자가 원하는 댄스 클래스와 수강 유형을 선택하고 '신청 내용 확인하기' 버튼을 클릭한다.
- **조건:** 클래스와 수강 유형을 선택했는가? Mix 4회 선택 시 서로 다른 두 클래스를 선택했는가?
- **반응·다음 상태:** 필수 항목이 누락되거나 Mix 4회에서 동일한 클래스를 선택하면 오류 메시지를 표시한다. 조건을 충족하면 선택 정보를 저장하고 신청 내용 확인 단계로 이동한다. '이전' 버튼을 누르면 신청자 정보 입력 단계로 돌아간다.

#### 4) 신청 내용 확인

- **행동·이벤트:** 사용자가 이름, 휴대전화 번호, 신청 클래스, 수강 유형을 확인하고 '이전' 또는 '신청 완료하기' 버튼을 클릭한다.
- **조건:** 사용자가 이전 단계로 이동하는가, 신청 절차를 완료하는가?
- **반응·다음 상태:** '이전' 버튼을 누르면 기존 입력값을 유지한 상태로 수강 조건 선택 단계로 돌아간다. '신청 완료하기' 버튼을 누르면 완료 안내 화면으로 이동한다.

#### 5) 신청 완료 및 다시 신청

- **행동·이벤트:** 사용자가 신청 완료 안내를 확인하고 '다시 신청하기' 버튼을 클릭한다.
- **조건:** 다시 신청하기를 선택했는가?
- **반응·다음 상태:** 신청자 정보와 수강 조건을 초기화하고 첫 번째 입력 단계로 이동한다. 새로운 신청을 진행할 수 있도록 입력 화면을 표시한다.

### 4. 구현 내용

- 기존 수강 신청 영역을 신청자 정보 입력, 수강 조건 선택, 신청 내용 확인의 3단계 프로토타입으로 변경했다.
- HTML의 `dialog` 요소와 JavaScript의 `showModal()`, `close()`를 사용하여 수강 신청 안내 팝업을 구현했다.
- `showStep()` 함수와 `hidden` 속성을 사용하여 현재 단계에 해당하는 화면만 표시하도록 했다.
- 진행 단계 표시 영역을 추가하여 사용자가 현재 신청 단계를 확인할 수 있도록 했다.
- 이름의 입력 여부와 휴대전화 번호 형식을 검사하고, 오류가 발생하면 안내 메시지와 입력창 스타일을 변경하도록 했다.
- 휴대전화 번호 입력 시 `input` 이벤트를 사용하여 `010-1234-5678` 형식으로 자동 변환되도록 했다.
- 수강 유형 선택에 `change` 이벤트를 연결하여 Mix 4회를 선택하면 두 번째 클래스 선택창이 나타나도록 했다.
- Mix 4회 선택 시 두 클래스가 서로 다른지 검사하는 조건문을 추가했다.
- `formData` 객체를 사용하여 단계 이동 시 입력한 신청 정보를 유지하도록 했다.
- 신청 내용 확인 단계에서 이름, 휴대전화 번호, 클래스, 수강 유형을 표시하도록 했다.
- '이전' 버튼을 통해 이전 단계로 돌아가 입력 정보를 수정할 수 있도록 했다.
- `submit` 이벤트와 `event.preventDefault()`를 사용하여 페이지 새로고침 없이 신청 완료 화면으로 전환되도록 했다.
- '다시 신청하기' 버튼을 클릭하면 입력값, 저장 정보, 오류 상태, 확인 내용, 완료 메시지를 초기화하고 진행 표시를 첫 입력 단계로 되돌린다.
- 수강 유형 변경 시 오류 문구와 해당 오류 스타일·접근성 속성을 함께 해제한다.
- 최종 제출은 확인 단계에서만 허용하며, 신청자 정보와 수강 조건을 다시 검증한다.
- 기존 클래스 소개 탭과 무료 체험 수업 기능을 유지하고, 단계형 수강 신청 영역에 반응형 CSS를 적용했다.

### 5. 실행 확인 및 테스트 결과

- 수강 신청 시작 버튼을 클릭하면 안내 팝업이 표시되고, '돌아가기'와 '신청 시작하기' 버튼이 정상적으로 작동하는 것을 확인했다.
- 이름과 휴대전화 번호가 비어 있으면 오류 메시지가 표시되고 다음 단계로 이동하지 않는 것을 확인했다.
- 휴대전화 번호를 입력하면 `010-1234-5678` 형식으로 자동 변환되는 것을 확인했다.
- 이름과 휴대전화 번호를 올바르게 입력하면 수강 조건 선택 단계로 이동하는 것을 확인했다.
- Mix 4회 선택 시 두 번째 클래스 선택창이 표시되는 것을 확인했다.
- Mix 4회에서 두 번째 클래스를 선택하지 않거나 동일한 클래스를 선택하면 오류 메시지가 표시되는 것을 확인했다.
- 서로 다른 두 클래스를 선택하면 신청 내용 확인 단계로 정상적으로 이동하는 것을 확인했다.
- Mix 4회에서 일반 수강 유형으로 변경하면 두 번째 클래스 선택창이 사라지고 신청 내용에도 반영되는 것을 확인했다.
- '이전' 버튼을 눌러 앞 단계로 이동해도 입력값이 유지되며, 수정한 정보가 최종 확인 화면에 반영되는 것을 확인했다.
- 신청 완료 화면이 정상적으로 표시되고, '다시 신청하기' 버튼을 누르면 입력값과 선택 상태가 초기화되는 것을 확인했다.
- 1100px, 768px, 390px 화면 너비에서 안내 팝업, 진행 단계, 입력창, 버튼 및 신청 내용이 화면 크기에 맞게 표시되는 것을 확인했다.
- 기존 클래스 소개 탭과 무료 체험 수업 기능이 정상적으로 유지되는 것을 확인했다.

## 8주차 중간 프로토타입: 내 신청 내역 조회·취소

### 1. 7주차 대비 추가한 기능과 사용자 목표

7주차 신청 완료 흐름에 이어, 완료한 신청을 목록에 저장하고 상세 내용을 다시 열어 확인하거나 취소하는 경로를 추가했다. `localStorage`에 저장하여 같은 브라우저·같은 사이트에서 새로고침한 뒤에도 신청 내역과 취소 상태를 복원한다.

- **주요 사용자:** 수강 신청 절차를 완료한 뒤 신청 내용을 확인하거나 신청을 취소하려는 사람
- **서비스 목적:** 클래스 탐색과 신청에서 끝나지 않고 완료 내역 관리까지 연결한다.
- **주요 행동:** 신청 완료 → 내 신청 내역 보기 → 상세 보기 → 신청 유지 또는 취소
- **완료 조건:** 선택한 신청의 정확한 정보를 확인하거나, 취소 확정 후 목록과 상세 화면에 ‘취소됨’이 표시된다.
- 상단 메뉴와 완료 화면의 ‘내 신청 내역 보기’에서 목록으로 이동한다. 별도 로그인·서버 접수 기능은 없다.

### 3. 구현 구분과 저장 범위

- `index.html`: 신청 내역 메뉴·완료 화면 링크, 빈 목록, 목록 영역, 상세 대화상자와 취소 확인 안내
- `style.css`: 신청 카드, 텍스트와 색으로 구분하는 상태 표시, 모바일 한 열 배치, 상세 대화상자 내부 스크롤 및 긴 내용 줄바꿈
- `script.js`: 이벤트 연결, 신청별 ID 생성, 목록·상세 갱신, 조건 검사, 취소 상태 저장, 저장 데이터 검증·복원
- 목록에는 클래스·유형·신청일·상태를 표시하고 이름과 전화번호는 상세 화면에 표시한다. 입력 내용은 `textContent`로 출력한다.
- 실제 접수가 아닌 프로토타입이다. 저장 정보는 같은 브라우저 프로필과 사이트에서만 유지되며 다른 기기와 공유되지 않는다. 사이트 데이터를 지우면 내역도 삭제된다.
- 저장소를 읽지 못하면 원래 저장 내용을 덮어쓰지 않고 임시 모드로 동작한다. 저장에 실패하면 새로고침 시 변경 내역을 잃을 수 있다.

## 9주차 입력 폼 개선

### 추가·수정한 기능

- 기존 안내 팝업 → 신청자 정보 → 수강 조건 → 확인 → 완료의 흐름과 디자인을 유지했다.
- 이름·전화번호·수강 유형·신청 클래스·Mix 추가 클래스에 `label`을 연결하고, `aria-describedby`로 도움말과 오류 안내를 연결했다.
- 기본 도움말은 이름 ‘이름은 2자 이상 입력해주세요.’, 전화번호 ‘010부터 입력해주세요.’다. 유효하게 입력하면 같은 도움말 한 줄을 각각 ‘이름 입력 조건을 충족했습니다.’, ‘전화번호 입력 조건을 충족했습니다.’로 바꾼다. 중복 상태 문구나 숫자 카운트는 추가하지 않는다. `aria-live="polite"`로 변경도 전달한다.
- 이름은 앞뒤 공백을 제외한 2~30자다. `minlength="2"`, `maxlength="30"`와 JavaScript 검사를 적용하고 입력 중 조건 충족 여부를 문구로 표시한다.
- 전화번호는 010으로 시작하는 숫자 11자리이며, 하이픈을 자동으로 넣고 입력 중 조건 충족 여부를 안내한다.
- 처음 열거나 다시 신청한 빈 입력창은 흰색 기본 상태이며 오류 문구는 비어 있다. 한 항목을 입력해도 아직 입력하지 않은 다른 항목에 오류를 표시하지 않는다.
- 유효하지 않은 입력에는 수정 방법과 `aria-invalid`를 표시한다. 입력했다고 무조건 오류를 지우지 않고, 조건을 충족하면 해제한다.
- 수강 조건 순서를 **수강 유형 → 신청 클래스 → 함께 수강할 클래스(Mix)**로 변경했다. 각 선택창에 별도 오류 문구를 두어 다른 항목의 오류가 잘못 지워지지 않게 했다.
- Mix 4회 선택 시 추가 영역의 `hidden`을 해제하고 선택창을 활성화·필수 처리한다. 일반 유형으로 전환하면 숨김·`disabled`·필수 해제·선택값 초기화를 함께 처리한다.
- Dance Starter와 K-POP Challenge를 제거했다. 클래스 소개는 Dance-eter, Easy Shuffle, Kids K-POP, K-POP Dance의 종류별 탭을 유지한다. 신청·Mix 선택창만 Kids K-POP 오후 4시/5시, K-POP Dance 오후 7시/8시로 구분한다.
- 이름·전화번호 오류 문구를 기존 위치보다 5px 위로 이동했다. 폼 내부 도움말의 세로 간격을 줄이고 빈 오류 영역은 숨겨 불필요한 여백을 없앴다.
- `submit` 이벤트에서 최종 검증 후 저장한다. 처리 중 ‘저장 중…’ 안내, 버튼 비활성화, `isSubmitting` 및 `aria-busy`로 중복 제출을 막는다. 서버 없는 과제에서 처리 중 상태를 볼 수 있도록 600ms 대기를 둔다.
- 저장 성공 시 완료 안내와 기존 신청 목록을 갱신한다. 실패하면 확인 화면·입력값을 유지하고 ‘다시 시도하기’를 활성화한다. 쓰기가 성공하기 전에는 새 내역을 목록에 추가하지 않으므로 재시도 시 중복되지 않는다.
- 저장소 읽기 실패나 손상 데이터는 기존 내용을 덮어쓰지 않고 제출 실패로 처리한다. 재시도할 때 저장소 읽기부터 다시 시도한다. 이는 8주차의 새 신청 임시 저장 동작을 변경한 부분이다.
- 다시 신청 시 입력·선택·오류·조건 안내·제출 안내·버튼·Mix 비활성화 상태를 초기화하고 기존 완료·취소 내역은 유지한다.

### 브라우저 확인 순서

1. 로컬 `index.html`을 브라우저로 연다. 저장 기능은 같은 브라우저·같은 주소에서 확인한다. 로컬 서버를 사용하려면 프로젝트 폴더에서 `python3 -m http.server 8765 --bind 127.0.0.1`을 실행하고 `http://127.0.0.1:8765`를 연다.
2. 수강 신청을 시작하고 이름·전화번호를 비운 채 다음 단계 버튼을 누른다. 이동 차단, 오류 문구와 첫 오류 항목으로의 초점을 확인한다.
3. 입력 전에는 기본 도움말만 보이는지 확인한다. 이름 한 글자, 잘못된 전화번호를 입력한다. 오류가 유지되는지 확인하고 이름 2~30자와 `01000000000`으로 수정한다. 기존 도움말이 조건 충족 문구로 바뀌는지, 자동 하이픈과 오류 해제가 동작하는지 확인한다. 다시 잘못 입력하면 기본 도움말과 오류가 표시되는지 확인한다. 30자 초과 입력은 제한된다.
4. 수강 유형·클래스를 비운 채 다음 단계 버튼을 눌러 각 오류를 확인한다. Mix 4회를 선택하고 추가 선택창이 표시·활성화되는지 확인한다.
5. 두 선택창에서 같은 항목을 고르면 오류가 표시되고, 다른 항목으로 수정하면 해제되는지 확인한다. 첫 번째 선택을 바꿔 두 선택이 같아진 경우도 검사한다.
6. 일반 유형으로 바꾸면 추가 선택창이 숨겨지고 비활성화되며 값이 지워지는지 확인한다. Mix로 다시 돌아오면 새로 선택해야 한다.
7. 유효한 신청을 확인 단계에서 제출한다. ‘저장 중…’과 비활성화된 버튼, 완료 안내, 목록 한 건 추가를 확인한다. 상세 조회·취소와 새로고침 후 복원도 확인한다.
8. 다시 신청하면 값·오류·조건 안내·버튼·Mix 상태가 초기화되고 기존 내역은 남는지 확인한다. 기존 클래스 소개 탭과 무료 체험 기능도 확인한다.

### 실패 처리 조건과 코드 위치

- `script.js`의 `registerForm`에 연결한 비동기 `submit` 처리: `try/catch/finally`로 성공·실패 안내 및 버튼 복구.
- `addRegistration()`: 저장소를 다시 읽고 새 목록을 만든 다음 `localStorage.setItem()` 성공 후에만 화면 목록을 갱신. 읽기 불가·손상 데이터·저장 공간 부족·브라우저의 저장 차단 시 실패한다.
- `loadRegistrations()`: 데이터 형식 검사와 기존 데이터 보호. 손상 데이터는 사용자가 별도로 복구해야 하며 무조건 덮어쓰지 않는다.
- 실패를 재현하려면 개발자 도구 콘솔에서 아래 코드를 실행한 뒤 확인 단계에서 제출한다. 입력 유지·실패 문구·재시도 버튼을 확인하고, 아래 복구 코드로 원래 저장 함수를 복구한 뒤 재시도한다. 이 코드는 저장된 내역을 삭제하지 않는다.

```js
// 1) 실패 재현: 이 줄만 실행하고 폼 제출
window.originalSetItem = Storage.prototype.setItem;
Storage.prototype.setItem = function () { throw new Error("9주차 저장 실패 확인"); };

// 2) 저장 기능 복구: 실패 화면을 확인한 다음 실행하고 ‘다시 시도하기’ 클릭
Storage.prototype.setItem = window.originalSetItem;
```

- 번들 Node.js로 JavaScript 문법 검사 및 `git diff --check` 통과.

### 9주차 최종 점검 후 취소 저장 보완

- 취소할 때도 최신 브라우저 저장 목록을 읽고 해당 신청만 취소 상태로 변경한다. 먼저 열어둔 탭에서 취소해도 다른 탭에서 추가한 신청 내역을 보존한다.
- 취소 저장이 성공한 뒤에만 메모리·목록·상세 상태를 변경한다. 실패하면 기존 신청 상태와 취소 확인 화면을 유지하며, ‘신청 취소하기’ 버튼으로 재시도할 수 있다.
- 다른 탭에서 이미 취소된 신청은 최신 취소 상태로 갱신한다. 내역 읽기 실패·손상 데이터·없는 신청은 저장을 중단하고 기존 데이터를 보호한다.
- 코드 위치: `script.js`의 `cancelRegistration()` 및 `confirmCancellation` 클릭 처리. 취소와 새 신청 모두 쓰기 성공 후 화면을 갱신한다.
- 확인 순서: 같은 사이트를 두 탭에서 연다 → 두 번째 탭에서 새 신청 → 첫 번째 탭에서 기존 신청 취소 → 새로고침 후 새 신청과 기존 취소 내역이 모두 남는지 확인한다.
- 실패 확인: 위의 저장 실패 재현 코드를 실행 → 상세에서 취소 확정 → 기존 상태 유지·실패 안내 확인 → 저장 함수 복구 → 같은 취소 버튼으로 재시도 → 취소 성공 확인. 실패 후 취소를 재시도하지 않고 새 신청을 하더라도 기존 신청은 원래 상태를 유지한다.
- 모의 DOM·공유 저장소 검사로 여러 탭의 순차적인 신청·취소, 취소 저장 실패·재시도, 실패 후 새 신청, 이미 취소된 내역 재확인 및 손상 데이터 보호를 검증했다. 여러 탭이 정확히 동시에 쓰는 상황의 완전한 동기화는 서버 없는 `localStorage` 구현 범위에 포함하지 않는다.
